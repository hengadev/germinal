# Germinal — agent crib sheet

SvelteKit 2 + Svelte 5 (runes), TypeScript, Drizzle ORM on PostgreSQL, Tailwind 4, pnpm. Read `CONTEXT.md` for the domain language (use its terms in code, UI copy and commits) and `docs/adr/` for decisions in the area you touch.

## Work cheaply

Every tool call resends the whole conversation, so calls and big outputs cost more and more as you go.

- **Don't explore broadly.** The issue and this file tell you where things are. Use `grep -n` / `rg` to find the exact spot, then read only that range (`sed -n 'a,bp'`). Never `cat` a large file. `schema.ts` (~1000 lines) and `services/email.ts` (~1400 lines) especially.
- **Trim every command's output:** `… 2>&1 | tail -40`, `grep -c`, `head`.
- **Batch:** one bash call can run several commands joined with `&&` or `;`.
- **Never write throwaway probe tests** to discover how things work. The answers are below.
- **Run only the tests you touch while working; run the full suites once at the end.**

## Layout

- `src/lib/server/db/schema.ts`: every table, enum and relation.
- `src/lib/server/services/*.ts`: domain logic. Routes stay thin and call services.
- `src/lib/server/auth-guards.ts`: `requireAdmin(locals)`, `requireStaff(locals)` (Staff or Admin), `requireAuth`.
- `src/lib/server/services/audit-log.ts`: `recordAuditLog(...)` for admin-side changes.
- `src/lib/server/services/email.ts`: transactional emails. Each has a text generator, an HTML generator and a `send…Email` function. Add new ones next to a similar one (e.g. the cancellation email).
- `src/lib/server/services/reservation-transitions.ts`: every Reservation status change, as single conditional updates. Follow its pattern for anything concurrency-sensitive.
- `src/lib/utils/event-time.ts`: Time Zone and Day helpers. Event times are on the Event's clock (ADR 0006).
- Routes:
  - `src/routes/(public)`: public site, i18n via `src/lib/i18n`;
  - `src/routes/(admin)/admin`: back office, **French only**;
  - `src/routes/(staff)/staff`: Staff portal, **French only**;
  - `src/routes/api/…`: JSON endpoints.
- Admin and Staff live on their own subdomains (`locals.isAdminDomain`, `locals.isStaffDomain`). The layouts' `+layout.server.ts` enforce it.
- UI kit: `src/lib/components/ui/bits-components` (Tabs, …), `Modal.svelte`, `Drawer.svelte`, `src/lib/components/toast`, icons from `lucide-svelte`. Copy the patterns of a neighbouring admin page.
- `env.USE_MOCK_DATA`: some loaders have a mock branch. Keep existing ones compiling. New code doesn't need one unless its route already has one.
- PWA: already set up on every subdomain. It has a per-hostname manifest at `src/routes/manifest.webmanifest/+server.ts` and a Workbox service worker configured in `vite.config.ts`.
- `PRODUCT.md` / `DESIGN.md` govern the **public** site only. Admin and Staff follow the existing back office.

## Commands

The orchestrator has already prepared this worktree: `node_modules` installed, `.env` linked, and `DATABASE_URL` and `TEST_DATABASE_URL` both pointing at **this worktree's own test database**, already migrated. Don't create databases or touch other ones.

| What | Command |
|---|---|
| One unit test file | `pnpm vitest run tests/unit/lib/x.test.ts 2>&1 \| tail -30` |
| One integration test file | `pnpm test:integration tests/integration/x.test.ts 2>&1 \| tail -30` |
| All unit tests | `pnpm test 2>&1 \| tail -30` |
| All integration tests | `pnpm test:integration 2>&1 \| tail -30` |
| Type errors **you** introduced | `$ORCH_SCRIPTS/check-new-errors.sh $ORCH_BASELINE` |
| Generate a migration after editing `schema.ts` | `pnpm drizzle-kit generate --name <snake_case_name>` |
| Apply migrations to your test DB | `node scripts/migrate.js` |

- **`pnpm check` reports ~70 errors that already exist on main.** Don't fix them and don't run it raw. `check-new-errors.sh` prints only errors that are not in the baseline (exit 0 = none). Without `$ORCH_SCRIPTS`, run `pnpm check --threshold error 2>&1 | grep -F '<files you changed>'`.
- **Tests:**
  - Unit tests: `tests/unit/{lib,services,guards,routes,validators}`, jsdom.
  - Integration tests: `tests/integration`, real database, files run one at a time.
  - Integration helpers live in `tests/fixtures/database.ts`:
    - `getTestDatabase()`;
    - `setupTestDatabase()`, which truncates the main tables (add your new tables to it);
    - `closeTestDatabase()`;
    - `seedServiceForSession(db, eventId, start, end, price?)`, which creates the Day and Service a Seating needs.
  - Copy the setup of a neighbouring integration test (e.g. `create-reservation.test.ts`, `internal-notes.test.ts`, `reservation-balance-export.test.ts`).
- **Migrations:**
  - Always generated by drizzle-kit, never hand-numbered.
  - SQL in `drizzle/migrations/NNNN_name.sql`, plus `meta/` snapshot and journal (commit all three).
  - CI fails on schema drift.
  - `ALTER TYPE … ADD VALUE` statements are handled specially by `scripts/migrate.js`. Read its header before adding an enum value.

## Git

- Conventional commits (`feat(staff): …`, `fix(admin): …`), with a subject that says what the user can now do.
- Never add a `Co-Authored-By` trailer.
- Never `git stash` (it is shared across worktrees), never push, rebase or switch branches.
